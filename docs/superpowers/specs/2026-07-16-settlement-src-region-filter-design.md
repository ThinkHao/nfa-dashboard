# 院校结算节点源区域筛选设计

## 背景与目标

`nfa_school` 已引入 `src_region`，用于表示院校关系实际使用的节点源区域。院校结算查询目前只有 `region`（院校归属区域）筛选，无法按节点源区域查询。

本次为院校结算结果保存 `src_region` 历史快照，并在查询页面增加可选的“节点源区域”筛选。历史记录不随 `nfa_school.src_region` 后续变化而变化；现有历史记录在上线迁移时按当前映射一次性回填并固定。

## 页面与筛选语义

过滤栏保留现有整体结构。在“服务月份”后依次排列：

1. 节点源区域
2. 院校归属区域
3. CP
4. 学校

原“地区”文案改为“院校归属区域”。请求新增可选参数 `src_region`，原参数 `region` 的含义和兼容性不变。

服务月份范围继续必填，最大跨度继续为 12 个月。用户、节点源区域、院校归属区域、CP、学校均为可选字段，允许全部为空或任意组合；查询不得新增字段间依赖或强制联动。

节点源区域选项来自当前用户可见院校范围内非空的 `nfa_school.src_region` 去重值。筛选采用精确匹配；`src_region IS NULL` 的历史记录不混入任何具体节点源区域。

明细响应与 CSV 导出增加 `src_region`，用户可见名称为“节点源区域”。

## 数据快照

以下结算表增加可空的 `src_region` 字段：

- `nfa_school_settlement`
- `settlement_customer`
- `settlement_customer_v`
- `settlement_customer_monthly`
- `settlement_customer_monthly_v`

新日结算生成时，按院校标识、院校归属区域和 CP 从对应的 `nfa_school` 关系复制 `src_region`。后续客户结算复算、月度聚合、双槽复制和切换都传递已有快照值，不重新读取当前映射覆盖历史值。

现有记录在迁移时按“院校标识 + 院校归属区域 + CP”与 `nfa_school` 唯一匹配并一次性回填。缺少院校标识的派生表，以其上游明细快照为准传播；无法唯一匹配的源记录保留 `NULL`，不得猜测写入。

回填必须幂等，只填充空值，不覆盖已经存在的历史快照。迁移执行前后输出或可查询总记录数、成功匹配数和未匹配数；迁移失败时事务回滚，避免部分回填。

## API 与查询链路

院校结算明细、月度聚合、导出和用户选项接口均接受可选 `src_region`。控制器将参数传入统一的结算筛选对象，服务层和仓库层沿用同一精确过滤语义。

前端所有结算请求共用参数构造逻辑：仅当节点源区域非空时发送 `src_region`。节点源区域不会改变用户、院校归属区域、CP 或学校是否可选。

查询直接过滤结算快照列，不在分页计数、明细、月度聚合或用户选项查询时实时联查 `nfa_school`。这样既满足历史稳定性，也避免重复 JOIN。

## 性能设计

为新增筛选补充与现有访问路径相符的组合索引：

- 日明细表以服务日期和 `src_region` 为主要前导维度；双槽日明细表同时包含服务月份、活动槽位和 `src_region`。
- 月度表以服务月份和 `src_region` 为主要前导维度；双槽月度表同时包含服务月份、活动槽位和 `src_region`。

保留现有区域、CP、学校组合索引，不为所有可选字段排列建立索引。具体列顺序在实施时结合现有活动槽位查询条件确定，并通过迁移测试和数据库 `EXPLAIN` 校验。

至少检查以下查询形态：

1. 仅服务月份范围。
2. 服务月份范围 + 节点源区域。
3. 服务月份范围 + 节点源区域 + 院校归属区域 + CP。
4. 上述条件再组合用户或学校筛选。

如果本机没有可用的兼容数据库，只能报告静态索引审查与自动化测试结果，不把真实执行计划标记为已验证。

## 错误处理与兼容性

- `src_region` 为空时保持现有查询行为和返回范围。
- 旧客户端不发送 `src_region` 时无需修改。
- 历史未匹配记录保留 `NULL`，仍可在不指定节点源区域时查询。
- 回填歧义必须形成可复核统计，不以任意一条映射代替。
- 数据库迁移需同步编号 SQL、`sql/migrations/`、离线安装包及 schema 预检。

## 范围边界

本次不新增源区域历史维表，不改变 `nfa_school.src_region` 的维护规则，不为筛选项增加级联强制关系，也不重构无关结算逻辑。
