# 院校结算查询面板设计

- 日期：2026-07-16
- 状态：已确认方案，待规格复核
- 涉及仓库：`nfa-dashboard`

## 1. 背景与目标

现有“单用户结算查询”面板强制选择用户，只能查询与指定用户相关的结算金额。实际业务还需要按地区、CP、学校等维度查询整个范围内的院校结算数据，例如只选择“北京区域 + bilibili”查看该范围内所有院校的结算结果。

本次将面板调整为通用的“院校结算查询”：服务月份仍为必选条件，用户、地区、CP、学校均为可选条件，并允许任意组合筛选。

## 2. 已确认的查询语义

| 字段 | 是否必选 | 说明 |
|---|---:|---|
| 服务月份 | 是 | 保留现有最多 12 个月限制 |
| 用户 | 否 | 选择后沿用现有费用归属人过滤语义；不选择时查询全部归属金额 |
| 地区 | 否 | 可单独或与其他字段组合筛选 |
| CP | 否 | 可单独或与其他字段组合筛选 |
| 学校 | 否 | 可单独或与其他字段组合筛选 |
| 粒度 | 是（有默认值） | 保留“按月/按日”现有行为 |
| 查看视图 | 是（有默认值） | 保留“明细视图/按月列视图”现有行为 |

用户、地区、CP、学校全部为空时，允许按必选的服务月份范围查询全部院校结算数据。

## 3. 实现方案

采用最小前端调整，复用现有后端接口：

- `GET /api/v1/settlement/data/customer`
- `GET /api/v1/settlement/data/customer/monthly`

现有后端已经将 `channel_owner_user_id` 作为可选过滤条件。参数不存在时按地区、CP、学校和月份范围查询全部数据，因此不新增接口、不改变数据库聚合逻辑。

前端构造请求参数时，仅在用户确实已选择时发送 `channel_owner_user_id`。不得发送 `null`、空字符串或无效用户 ID。

## 4. 页面与命名

页面名称由“单用户结算查询”调整为“院校结算查询”，同步更新：

- 页面标题；
- 路由菜单标题；
- 首页工作台入口标题；
- 系统设置中描述该页面显示口径的用户可见文案。

组件文件名、路由路径、路由 name、API 方法名与导出文件名前缀保持不变，以减少无业务收益的兼容性改动。现有 CSS 根类名也不调整。

## 5. 查询与交互流程

1. 用户选择必填的服务月份范围。
2. 用户可选填用户、地区、CP、学校中的任意字段。
3. 点击查询时，前端仅校验月份范围存在且不超过 12 个月。
4. 前端按已填写字段构造参数；未填写的可选字段不进入请求。
5. 后端按现有权限、有效流量范围和筛选条件返回分页结果。
6. 查询、翻页、刷新、导出和按月列视图加载必须使用同一套可选参数规则。

重置操作继续清空用户、地区、CP、学校，并恢复默认粒度、默认视图与默认月份范围。

## 6. 金额展示语义

### 明细视图

保持现有列结构，继续显示：

- 客户金额；
- 线路金额；
- 节点金额；
- 渠道金额；
- 总归属金额。

不选择用户时，各金额字段显示筛选范围内完整结算结果。选择用户时，后端继续按现有规则，仅返回该用户在客户、线路、节点或渠道归属字段中匹配的金额。

### 按月列视图

保持原样，不拆分金额类型。每个月继续显示“日95均值”和现有合计“金额”列；底部总和与区域/学校/CP 树形汇总规则不变。

## 7. 权限与性能边界

- 继续使用现有 `/api/v1` 接口及 `settlement.data.read` 权限，不扩大用户的数据可见范围。
- 服务月份必须选择且最多 12 个月，避免无界全历史查询。
- 不改变分页大小、按月列视图全量分页拉取方式或后端月快照选择逻辑。
- 不改变费用归属过滤、日95计算、金额汇总及进制换算规则。

## 8. 错误处理

- 未选择服务月份时提示“请先选择服务月份范围”。
- 查询跨度超过 12 个月时保留现有提示。
- 查询、按月列视图和导出的接口错误继续沿用现有错误提示与取消请求处理。
- 用户为空不是错误，不显示警告。

## 9. 测试与验收

增加可独立测试的查询参数与校验逻辑，覆盖：

1. 未选择用户、仅选择地区和 CP 时，请求不含 `channel_owner_user_id`，但包含月份、地区和 CP。
2. 选择用户时，请求包含正确的 `channel_owner_user_id`。
3. 用户、地区、CP、学校均为空但月份有效时允许查询。
4. 月份为空时拒绝查询；超过 12 个月时拒绝查询。
5. 明细、按月列、导出和翻页复用相同的参数生成规则。
6. 页面、路由、工作台和系统设置中的用户可见名称均为“院校结算查询”。
7. 现有按月列视图测试继续通过，证明金额列没有被拆分或改变。

## 10. 不做

- 不修改结算金额和日95计算口径。
- 不把按月列视图拆成多类金额列。
- 不重命名组件文件、路由路径、路由 name、CLI 命令或导出文件名前缀。
- 不新增筛选字段或汇总卡片。
