# NFA 院校服务源区域设计

## 目标

在 `nfa_school`（NFA 院校关系表）中增加 `src_region` 字段，用于记录每个“院校 + 所属区域 + 业务”关系实际使用的服务源区域；提供默认只读的全量回填预览，并且只在人工确认后执行数据库更新。

## 数据来源与口径

- 目标数据：当前数据库中的 `nfa_school` 全量记录。
- 本地业务节点来源：飞书电子表格“EDC运维信息表”的 `EDC节点` 工作表。
- 只有 `状态=正常` 的 EDC 节点才表示该省存在本地业务节点。
- 北京阿里节点状态为空，但阿里专项规则优先，因此不依赖正常节点判断。
- 本次读取到的表格范围为 `EDC节点!A1:Z40`。实际生成预览时，工具使用内置且经过确认的“正常节点省份 + 标准业务”集合，避免运行时依赖飞书权限或表格可用性。

## 字段设计

- 表：`nfa_school`
- 字段：`src_region VARCHAR(20) NULL`
- 含义：院校对应业务的服务源区域。
- 初始允许 `NULL`，以明确区分“尚未回填”与有效区域。
- 迁移必须幂等，并声明运行时列契约。
- Go `School` 模型增加对应字段，JSON 名为 `src_region`。
- 离线部署 schema 预检增加 `nfa_school.src_region` 检查。

## 业务名称映射

数据库中的标准 CP 与 EDC 表业务名称对应如下：

| 标准 CP | EDC 业务名称 |
| --- | --- |
| `bilibili` | B站 |
| `ali` | 阿里 |
| `jsy` | 金山 |
| `cnc` | 网宿 |
| `bsy` | 白山 |
| `xinliu` | 新流 |

不在映射中的 CP 不做猜测，进入预览异常清单，并且执行时跳过。

## 回填规则与优先级

规则按以下顺序匹配，命中后停止：

1. `region=广东 AND cp=ali`：`src_region=广东`。
2. 其他 `cp=ali`：`src_region=北京`。
3. `region=江苏 AND cp IN (jsy, cnc)`：`src_region=上海`。
4. `region=吉林 AND cp=bilibili`：`src_region=北京`。
5. 当前“省份 + 标准业务”在 EDC 表存在 `状态=正常` 节点：`src_region` 与该记录当前 `region` 原值一致。
6. 其他 `cp=bilibili`：`src_region=天津`。
7. 其他已识别业务：`src_region=北京`。

专项规则优先于通用的本地节点规则。省份比较时允许去除尾部“省/市/自治区”等行政区后缀进行判断，但规则 5 写回时保留 `nfa_school.region` 原值；专项规则写入明确值“广东、北京、上海、天津”。

## 预览与执行

提供独立回填工具，默认模式只读：

- 查询 `nfa_school` 全量记录。
- 为每行计算目标 `src_region` 和命中规则。
- 不修改数据库。
- 输出 JSON 预览文件，包含总数、将更新数、无需更新数、异常数、规则分桶、逐行明细及异常清单。
- 明细至少包含记录 ID、院校、原区域、标准 CP、当前值、目标值和命中规则。

实际执行必须同时提供显式执行和确认参数。执行流程：

1. 重新读取当前数据并重新计算，避免使用过期预览直接写入。
2. 创建带时间戳的完整备份表。
3. 只更新已识别且目标值确定、当前值不同的记录。
4. 在同一数据库事务中完成备份与更新；失败则回滚。
5. 提交后重新读取并验证所有可处理行均等于预期值。
6. 输出更新数、跳过数、异常数、备份表名和验证结果。

## 测试

单元测试覆盖规则优先级、业务映射和异常处理，至少包括：

- 陕西 `bilibili` → 天津。
- 陕西其他已识别业务 → 北京。
- 广东 `ali` → 广东，其他省份 `ali` → 北京。
- 江苏 `jsy/cnc` → 上海。
- 吉林 `bilibili` → 北京。
- 正常本地节点命中后使用原 `region`。
- 下线或筹建节点不构成本地节点。
- 未识别 CP 进入异常且不更新。

迁移完成前运行 SQL migration guard；实现完成后运行回填工具单元测试、相关 Go 测试、离线 schema 检查静态核对及 `git diff --check`。

## 范围与风险

- 本次不新增后台管理 API 或前端编辑入口。
- 本次不修改飞书表格。
- 本次不在用户确认预览前执行数据库回填。
- `nfa_school` 的上游生产/同步程序不在本仓库中；如果上游以全量替换方式重建表，后续需要同步支持 `src_region`，否则新生成记录仍可能为 `NULL`。预览交付时必须再次报告这一持续写入风险。
